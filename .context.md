# TER Context Overview

**Status:** Stable (v1.4)
**Purpose:** Modular, portable Termux shell environment and system integration toolkit.

> Authoritative docs: `AGENTS.md` (agent workflow), `CLAUDE.md` (architecture
> map, files written outside the repo), `README.md` (user guide),
> `docs/cli_manual.md` (command reference). This file is a summary only.

## Architecture

1. **Source repository (`~/ter/`, this repo)** — where all development happens.
2. **Active environment (`~/.shell.d/`)** — deployed copy sourced at startup.

Deploy **only** via `bash install.sh`. Never deploy with `cp -r ~/ter/* ~/.shell.d/`
(that would copy `.git`, `extras/`, and root artifacts into the runtime).

## Module layout (`~/.shell.d/`)

- `core/`: styling (`00-style.sh`), config + secrets (`01-config.sh`), prompt themes, alias manager (`alm`), app registry loader (`app-loader.sh`).
- `user/`: aliases, tab titling, tmux helper (`02-tmux.sh`), background stability engine (`optimize.py` wrapped by `optimize.sh`, startup one-liner in `z-run.sh`), ADB utilities (`adb_utils.sh`, `adb-audit.py`, `adb-manage.py`, `adb_common.py`).
- `network/`: `adb_connect.sh` (`adbcon`) and subnet scanners (`scan.sh`).
- `apps/<name>/`: third-party registrations (manifest.json + auto-sourced *.sh).

The tmux config lives at `.tmux.conf` in the repo; `install.sh` symlinks
`~/.tmux.conf` to it (mobile-friendly: `~` prefix, touch scrolling).

## Background stability engine (`optimize`)

Solves Android 12+ Phantom Process Killer issues and battery hibernation.
Requires local ADB loopback (`adbcon`). Checks degrade gracefully when ADB is
offline. Commands: `optimize status|fix|run|list|stop|log`.

## ADB connection wizard (`adbcon`)

Automates Wireless Debugging pairing/connection, then locks the server to the
offline `127.0.0.1:5555` loopback. Filters for true Wi-Fi/Hotspot interfaces
(ignores `rmnet`); gives step-by-step guidance instead of blocking.

## Development workflow

1. Edit files in this repo (never the deployed `~/.shell.d/` copy).
2. Verify: `bash smoke.sh`.
3. Deploy: `bash install.sh`; open a new terminal session to test (`re` does not re-run modules — per-PID loader guard).
4. Changing the MOTD: edit `make_motd.py`, run `python3 make_motd.py` (writes repo `motd` and copies to `/usr/etc/motd` if writable).
